# Mobile 网页

入口 `/mobile`，登录 `/mobile/login`；所有业务链接使用 mobile- 前缀命名路由。
手机访问未带 /mobile 的页面时由公共路由守卫分流，保留原路径、查询和锚点；电脑访问 /mobile 同样保持移动端。

views、components、features 和 layouts 均为独立实现，不导入 PC 的页面或私有组件。七类模板在移动端内部继续物理隔离。共享认证会话、HTTP/API 基础设施、类型工具、静态资源及后端接口；未增加数据库表或 API。

移动端导航使用顶部菜单及底部快捷导航，列表使用卡片，表单单列，弹窗支持窄屏。月度及周任务以逐条卡片填写，关键任务文本常显，其他字段分组折叠；沿用原有模板输入、附件、人员选择及子数据事件。标题行只保留新增与更多，客户标签独占一行，辅助工具收进更多操作面板。列宽列表存储增加 mobile 标识。

当前业务实现以 PC 版本为起点独立维护；后续业务规则变更需分别更新两端并验证，不允许直接导入 PC 私有页面替代。

验证：npm run type-check；npm run build；node scripts/test-mobile-entry.mjs（需要本机 Edge）。入口测试覆盖电脑、手机自动分流、电脑显式访问 Mobile、移动端深链接未登录入口。真实账号填报、审批、附件上传等完整业务仍需在部署环境验收。

服务器需将 /mobile 及其子路径按 SPA history 路由回退至 index.html，与现有 PC 深链接部署规则一致。
